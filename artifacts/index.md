# 产物规范

## 目标

约束全体产物的共性规则：每件产物是知识工作的标准文档件，在知识流动链中承担一个明确角色，配一份规格（目标/流程/验收三段）约束其维护方式。一般工作规则：先定义产物，再朝产物的方向走——我们定的这套标准产物即我们自己的标准案例，案例见[画廊](../../gallery/artifacts/index.md)。

## 流程

1. 注册：每件产物建一份规格，按「目标/流程/验收」三段编写。
2. 维护：按各自规格维护，共性规则为——
   - 角色唯一：一件产物只承担流动链中的一个角色，不得兼用；
   - 三段式流动：接收上游 → 本地加工 → 转出下游，内容只向下游流动，不得跳级或回流；
   - 单一去处：每条内容每次流动只有一个明确去处，不得一稿多投；
   - 不留副本：转出后上游不以原形式留存，每次流动上游净缩短，不得在原处保留副本；
   - 可再找到：暂无去处的留在原地等待，转出内容在下游可被再次找到，不得移出后在下游找不到；
   - 组织自主：规格只约束流动方式，不约束内部组织形态，不得借规范约束产物的内部编排。
3. 检验：新增产物的规格即对共性规则的检验，出现反例时修正规则而非硬套。

## 验收

- 每件产物有规格，格式为目标/流程/验收三段。
- 每条内容流动有单一去处，上游不留副本。
- 共性规则被全部产物规格遵守，反例出现时规则已同步修正。
- 未犯常见错误：把 `gallery.md` 改成 `case.md`、把标题「案例」写成「画廊」、自建 `deliberation/` 目录、把新实体硬塞进 `piece/` 或 `process/`、复制内容造第二事实源、规范里指涉 studio 实现、把定义写成类比与举例。
