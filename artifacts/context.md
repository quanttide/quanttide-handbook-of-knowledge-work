# 语境（context）

## 目标

context 是系统的驱动层：**系统（人或 AI）执行任何工作时读取的背景设定**——当前在做什么、依据什么规则、处于哪个阶段、注意什么边界。它回答"带着什么上下文干活"。

设计动机（2026-09-10 定）：此前 journal 既当捕获入口又当事实源，AI/新会话要理解"现在怎么做"必须翻日志历史——驱动信息与时间线混在一起，且靠翻历史拼凑上下文不可靠。把驱动职能单独成层后，**新会话读 context 即可获得执行所需的一切**，无需对话历史。

## 与其他工作物的分工

**context 无时态**——它不是对某个时点的陈述，而是当前生效的驱动规则；其他工作物都带时态（现在或未来）。

| 工作物 | 回答的问题 | 时态 |
|---|---|---|
| **context** | 现在带着什么上下文干活？ | **无时态**（当前生效的驱动） |
| journal | 这段时间发生了什么？ | 现在×事件 |
| 档案 | 我们知道什么？ | 现在×语义 |
| 意图 | 为什么 | 未来×自我 |
| 洞察 | 学到了什么 | 未来×语义 |
| 路线图 | 先做什么 | 未来×事件 |

## 与洞察的关系：新的 context 先以 insight 形态存在

context 与 insight 容易重复，分界是**时态与检验状态**：

- **insight**：带时态的规律认识（对未来的预测），可累积、可修正、可证伪——**新的驱动认识先在这里接受检验**
- **context**：无时态的驱动规则，只保留当前生效版本——**检验成立后才定型于此**

即：**新的 context 可以变成 insight**——刚形成的规则认识不直接写入 context，而先作为洞察存在（带预测与证伪条件）；实践检验成立后，才升格为无时态的语境规则。反向地，被替换下来的旧 context 不保留，其历史意义由洞察层的检验记录承担。

## 内容形态

按主题组织的语境文档（驱动规则、当前阶段、工作约定），每篇独立可被系统加载。仓库：`quanttide-context-of-knowledge-work`（data/context）。

## 流程

1. **转入（两类来源）**：
   - **洞察升格**：新的驱动认识先在洞察层接受检验（洞察是对未来的预测，带证伪条件）；**新的 context 先以 insight 形态存在**，检验成立后才定型为无时态的语境
   - **日志沉淀**：journal 整理中出现的稳定规则（如整理移出惯例、分流规则）转入
2. **修订**：规则变化时直接改 context 对应文档，journal 记一条状态变化（"X 规则改为 Y"）指向新版本；被替换的旧版本不保留（其历史意义由洞察层记录）
3. **加载**：系统执行工作前读 context 相关文档；context 是驱动，journal 只是它的时间线索引

## 验收

- 新会话/新成员只读 context 即可获得执行所需上下文，无需翻日志历史或对话记录
- context 中没有一次性事件（那些归 journal），journal 中没有驱动规则（那些归 context）
- 每条规则可溯源：或来自洞察升格（有检验记录），或来自 journal 沉淀（有分流记录）
- 规则变更可追溯：journal 的时间线 + context 的当前版本，两者对得上
